# 同じローカルLLMで比較する手順

このリポジトリに実測スコアは含めていません。以下は実測を追加するための評価設計です。

## 固定する条件

- 同じモデルID、量子化、サーバーバージョン、context上限、生成上限。
- 同じリポジトリの開始commit、タスク、受け入れテスト。
- 同じ時間予算と使用できる外部ツール。並列数もそろえる。
- 主モデル以外の要約・judge・subagentモデルとfallbackの接続先を記録する。
- ハーネスごとに独立したcheckout / worktreeを使い、他の実行の編集を混ぜない。

## タスク指示例

```text
対象: このリポジトリの src/parser と tests/parser。
目標: 空行を含む入力で失敗するケースを修正する。
完了条件:
- 失敗を再現する回帰テストが追加されている。
- 指定されたテストコマンドとビルドが成功する。
- 公開APIと既存の入力仕様は変えない。
手順: 調査→変更→検証→失敗時の修正を進める。
報告: 変更点、実行した検証、その終了結果、未完了事項を記録する。
停止条件: 予算上限、必要な外部情報の欠落、繰り返しても改善しない失敗。
```

`テストコマンド`は対象プロジェクトの実在するコマンドに置換します。ハーネスが編集できない場所にも評価用テストを保持すると、テストを消した／弱めたための見かけ上の成功を区別できます。

## 最小の測定表

| 項目 | 記録内容 |
| --- | --- |
| harness | 製品・バージョン・追加plugin・実行面 |
| model | モデルID・量子化・API形式・サーバー版 |
| task | 開始commit・指示ファイル・固定した検証コマンド |
| unattended | 人が追加入力せずに終了したか、介入回数 |
| completion | agentの完了申告と外部検証結果を別々に記録 |
| time | 総経過時間、最初の編集までの時間 |
| failure | 承認待ち、tool-call解析失敗、context超過、同じ修正の反復、未完了終了 |
| recovery | 中断後に何が復元されたか、再開に必要だった操作 |
| resources | 主・補助モデルのtoken、GPU使用、並列数 |
| artifact | 差分、ログ、終了コード、テスト結果 |

最初は一つの小さい実タスクを直列で比較し、接続とツール実行を確認してから長時間・並列運用へ広げます。ここでの手順は評価案であり、実施済みの結果ではありません。
